这是一份**使用指南**。它只说明工作流程与格式，不代表已经导入或评估任何论文。

## 一条工作流

论文网页或 arXiv 链接 → 获取元数据与正文 → 生成带来源的结构化笔记 → 自动建议分类 → 检查并保存 Markdown → Git 同步 → 静态网站。

网站负责阅读、搜索和组织内容。检索、模型调用和文件写入在本地工具中运行；GitHub Pages 不运行 Python 或 MCP 服务。

## 论文与调研分别保存

- **论文笔记**：一篇论文一份文件，位于 `content/papers/<id>.md`。保存稳定的论文标识、原文 URL、标签与处理状态。
- **专题调研**：一个问题一份报告，位于 `content/research/<slug>.md`。对比多篇论文，保留检索范围、纳入理由和尚未解决的问题。
- **个人补充**：把自己的判断与论文作者的主张分开写，避免重新总结时覆盖个人内容。

从[[papers/index|论文库]]查看单篇笔记，从[[research/index|专题调研]]阅读横向比较。

## 一篇可靠笔记应该记录什么

1. **问题与贡献**：论文要解决什么，作者提出了什么。
2. **方法**：输入、输出、训练数据和关键假设。
3. **具身实验**：机器人形态、任务、环境、真实/仿真设置、成功率定义和基线。
4. **证据**：章节、页码、表格或图编号；缺失的数据明确写为“未报告”。
5. **限制**：实验覆盖范围、泛化条件、复现材料和未验证结论。
6. **个人备注**：对自己研究的启发、疑问和后续实验。

只拿到摘要时应标明“仅基于摘要”，不能补写全文实验细节。自动标签可以修改，自动总结也需要核查。

## 分类用多个维度

可以同时使用任务、方法和平台标签，例如 `task/manipulation`、`method/vision-language-action`、`platform/mobile-manipulator`。这些只是格式示例，不表示库中已有对应论文。

标签不是互斥文件夹：同一篇论文可以属于多个主题；稳定的论文 ID 决定文件身份，调整标签不需要移动文件。

## 公式与链接

笔记支持行内公式 $p(a\mid o)$ 和块级公式。下面只用于检查公式渲染：

$$
\pi^* = \arg\max_{\pi}\;\mathbb{E}_{\pi}\left[\sum_{t=0}^{T}\gamma^t r_t\right].
$$

用 `[[guide/quickstart|显示文字]]` 连接相关笔记。网站会生成反向链接；左侧搜索在浏览器中检索已构建的笔记内容。

## 换一台电脑继续

克隆同一个仓库，按仓库 README 安装本地工具及网站依赖，然后拉取最新内容。在两台电脑上同时编辑同一篇笔记时，先检查 Git 差异并解决冲突，保留双方的人工备注。

PDF、缓存和模型密钥不应成为笔记 Git 历史的一部分。GitHub Pages 发布的是构建后的页面；发布范围以仓库的发布配置为准。
